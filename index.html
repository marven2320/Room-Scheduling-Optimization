Room Scheduling Optimization System

Add rooms, set their weekly availability, add subjects with class-hour durations, then optimize to auto-assign rooms and time slots. Optimization is powered by Genetic Algorithm.

Developed by the Department of Electrical Engineering, College of Engineering

Add a Room

Default availability is every day, 7:30 AM – 9:00 PM. Narrow the open/close times below to override the default for this room (rooms can't open earlier than 7:30 AM or stay open later than 9:00 PM) — or leave them as-is and fine-tune specific days/times afterward with "Edit Availability". For rooms shared with other departments, set Allowable Usage % below 100% to cap how much of the room's open time this app's optimizer is allowed to claim.

Rooms

Click "Edit Availability" to block off days/times a room can't be used.

Add a Subject

Set how long each class session runs and how many sessions per week it needs. Each session is scheduled on a different day. 3-hour Lecture subjects can optionally be split into two 1.5-hour sessions on paired days (Mon+Wed, Tue+Thu, or Fri+Sat), meeting at the same time on both days. Laboratory subjects can optionally be split into 2 identical sections when one room can't fit the whole class — each section keeps the full session length and is scheduled independently. Linking a subject to a Prospectus Course (uploaded in the Prospectus tab) lets the optimizer keep it conflict-free against the other required courses in the same program & year level for regular students — different programs are scheduled together but never block each other. Subjects handled by another college/department can be marked External Assignment — the optimizer will only place their class hours (room shows as TBA, faculty as TBD) while still avoiding conflicts for regular students.

Subjects

Add Faculty

List each faculty member's previously handled subjects. The optimizer will only assign a subject session to a faculty member listed here for it, and will never double-book a faculty member into two overlapping sessions — even across different rooms. One or more faculty can be listed for the same subject; leave a subject with no faculty listed to schedule it without a faculty-conflict check.

Faculty

Upload Program Prospectus

Upload one or more degree programs' prospectuses (curricula) so the optimizer can schedule them all together while keeping regular students conflict-free: every required course in the same program & year level is treated as something one student takes at some point, so none of them are ever scheduled to overlap — different programs (and different year levels) never block each other. Pick a Target Semester on the Schedule tab to auto-load every uploaded program's courses for that term as subjects. CSV import is the reliable option; PDF upload is best-effort (parses common "Year, Term" tabular prospectus layouts) and always shows a review step before anything is saved — always check it over. Courses already in your prospectus (same Program + Year + Term + Code) are automatically skipped as duplicates on re-import.

Prospectus Courses

Optimize & View Schedule

Runs a genetic algorithm — a population of candidate schedules evolved over generations via selection, crossover, and mutation — to fit every class session into a conflict-free room/day/time/faculty slot while maximizing room utilization and keeping Laboratory subjects within 7:30 AM–5:00 PM when possible. External Assignment subjects skip the room/faculty match and only get their class hours placed (TBA/TBD). If a Target Semester is set, regular-student conflicts are also enforced — separately for each program's year level (a 4-year program's term has 4 independent year-level cohorts checked at once; different year levels never block each other).

📘 Quick Start — Step by Step

The recommended order to set everything up. Every step's data is saved automatically to your browser as you go.

  1. Add your Rooms (Rooms tab)

    Give each room a name and, optionally, a seating capacity. Rooms default to open every day, 7:30 AM – 9:00 PM — the outer bound the app never lets a room go beyond. Narrow the hours at creation ("Open From" / "Open Until"), or fine-tune specific days/times afterward with Edit Availability on the room card. For a room shared with other departments, set Allowable Usage % below 100% — the optimizer will then cap how many of that room's weekly slots it's allowed to book, leaving the rest free for whoever else uses it.

  2. (Optional) Upload a Program Prospectus (Prospectus tab)

    If you want the optimizer to keep regular students' schedules conflict-free, upload your curriculum here first. Type a Program Name (e.g. "BS Electrical Engineering"), then either Import CSV (reliable — download the template for the exact columns) or Upload PDF (best-effort; always review the parsed rows before saving). You can upload multiple degree programs — courses already in your prospectus (same Program + Year + Term + Code) are automatically skipped as duplicates.

  3. Add Subjects (Subjects tab)

    Add each subject by hand — name, Lecture/Laboratory type, session duration, sessions per week, optional class size — or skip this if you uploaded a prospectus and let Step 5 load them automatically instead. Two special options:

    • Prospectus Course link — ties a subject to an uploaded course so the optimizer keeps it conflict-free against that program's other same-year-level courses.
    • External Assignment — check this for subjects handled by another college/department (e.g. NSTP, PE). The optimizer places only the class hours; room shows as TBA and faculty as TBD, with no room/faculty conflict-checking needed.
  4. (Optional) Add Faculty (Faculty tab)

    List each faculty member's previously-handled subjects. The optimizer only assigns a subject to a listed faculty member and never double-books one across two overlapping sessions — even in different rooms. Leave a subject off every faculty list to schedule it without a faculty-conflict check.

  5. Pick a Target Semester (Schedule tab — only if you uploaded a prospectus)

    Selecting First Semester / Second Semester / Summer Term loads every uploaded program's courses for that term straight into the Subjects tab, and turns on regular-student conflict-checking — kept separate per program and year level, so a 4-year program's term runs 4 independent checks at once without them blocking each other. Switching terms clears the entire Subjects tab first (you'll be asked to confirm) so the new term starts clean.

  6. Click "⚡ Optimize Scheduling"

    A progress modal shows the genetic algorithm converging live — fitness and room-utilization charts, generation/population counters, and (when a Target Semester is active) a Student Cohorts tile showing how many independent cohorts are being satisfied.

  7. Review the result

    Switch the View dropdown between Room Timetable, Faculty Schedule (pick a faculty member to see just their own weekly grid), Regular-Student Schedule (pick a program/year-level cohort to see everything a student in it takes), and List View. Anything that couldn't be placed appears separately under Scheduling Conflicts, split into Room / Faculty / Regular-Student groups, each with a specific reason — use that to decide whether to add a room, adjust availability, or change a subject's settings, then optimize again.

  8. Export or print

    Once you're happy with it, use 🖨 Print or ⬇ Export CSV on the Schedule tab — both act on whichever room, faculty member, or cohort you currently have selected, so you can hand out a clean per-faculty or per-student-cohort schedule without the rest of the data.

❓ Frequently Asked Questions

Where is my data stored? Is anything sent to a server?
Everything (rooms, subjects, faculty, prospectus, schedules) is saved only in your browser's local storage — nothing about your actual scheduling data is uploaded anywhere. Two exceptions: (1) the first time you use Upload PDF, a PDF-reading library is fetched from a public CDN so the app can read the file, though the PDF itself is still processed entirely in your browser; and (2) if the app is being served by server.py (rather than a plain static server), basic usage activity — page visits, which features get used, your IP address — is logged server-side to usage_log.csv for app-functionality testing, and summarized in the App Usage Summary tab.
Why can't a room open before 7:30 AM or stay open past 9:00 PM?
That's a fixed institutional bound the app enforces for every room — custom hours can only narrow that window, never widen it.
I selected a Target Semester and no subjects loaded — is that a bug?
Usually not — it means either no prospectus is uploaded yet, or none of your uploaded courses have a Term that reads exactly "First Semester", "Second Semester", or "Summer Term" (the app already tolerates common variants like "1st Semester" and old CSV files that predate the Program column, but very different wording won't match). The app will always tell you which of these happened instead of loading nothing silently — check the message after selecting the term.
What happens to my existing subjects when I switch the Target Semester?
Switching to a different term clears every subject currently in the Subjects tab (you'll be asked to confirm first) before loading the newly-selected term's courses. This keeps rosters from different terms from ending up mixed together. Selecting "— none —" doesn't clear anything, since there's nothing new to load.
What does "External Assignment" mean, and when should I use it?
Use it for a subject whose room and instructor are arranged by another college/department (common for NSTP, PE, or similar service courses). The optimizer skips room and faculty matching for it entirely and only figures out its class hours — room shows as TBA and faculty as TBD in the schedule. It still respects regular-student conflict-checking if linked to a Prospectus Course.
Can I upload more than one degree program's prospectus?
Yes — type a different Program Name before each upload. Courses are grouped and displayed by program in the Prospectus tab, and regular-student conflict-checking treats each program's own year level as an independent cohort, so different programs never block each other even when scheduled in the same run.
Why did a subject end up in "Scheduling Conflicts" instead of being scheduled?
Every unscheduled session is grouped by cause — Room (no free room/time big or long enough), Faculty (every listed faculty member already busy), or Regular-Student (would overlap another required course for the same program's year level) — each with a specific, actionable reason. Fix the underlying constraint (add a room, widen availability, add faculty, adjust the conflicting course) and click Optimize again.
Can I edit a room, subject, or faculty entry after adding it?
Room availability can be edited anytime via "Edit Availability". Subjects and faculty don't have a full edit form yet — delete and re-add with the corrected values. The one exception is External Assignment, which has its own "Mark/Unmark External" toggle right on the subject card.
The App Usage Summary tab says "No usage-tracking server detected" — why?
That tab reads live data from server.py, a small local server included in the project that serves the app and logs basic usage activity to usage_log.csv (timestamps, IP addresses, which features get used, optimizer generations/population, network latency, and any app errors — for functionality testing, not for the scheduling itself). If you started the app with the plain python3 -m http.server instead, that endpoint doesn't exist. Run python3 server.py from the project folder instead, then reload the page — everything else in the app works identically either way.
What's "Allowable Usage %" on a room, and when should I use it?
It's for rooms shared with other departments/colleges that this app doesn't control the full schedule of. Set it below 100% (e.g. 50%) and the optimizer will never book more than that share of the room's total weekly open slots — the rest stays free for whoever else uses the room. It defaults to 100% (fully available to this app) for every room unless you change it.
Found a bug — how do I report it?
Visit the Department of Electrical Engineering (DEE) website, linked in the footer of every page.
